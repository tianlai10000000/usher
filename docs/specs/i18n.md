# Internationalization / 国际化

## Scope / 范围

This specification owns packaged UI locales, locale selection and fallback,
Slint translation bundles, Rust-authored user-facing copy, and translation
maintenance gates. It does not translate logs, protocol values, provider
identifiers, file paths, model names, or remote server payloads.

本文负责内置 UI 语言、语言选择与回退、Slint 翻译 bundle、Rust 生成的用户可见
文案，以及翻译维护门禁。日志、协议值、Provider 标识、文件路径、模型名称和远端
服务返回内容不属于翻译范围。

This specification is a mandatory entry gate for every production UI change.
All new or changed user-facing copy, whether authored by Slint or projected by
Rust, must use the shared semantic catalog and remain correct after an immediate
runtime locale switch.

本文是所有生产 UI 改动的强制入口规范。无论文案来自 Slint 还是 Rust 动态投影，
所有新增或修改的用户可见文案都必须使用共享语义 catalog，并在运行时立即切换语言后
保持正确。

## Ownership / 职责

- `i18n/manifest.toml` is the locale registry. It owns canonical BCP-47-like
  ids, native display names, aliases, and per-locale coverage floors.
- `i18n/messages.toml` owns Slint-visible source messages, including those also
  consumed by Rust. `i18n/rust-messages.toml` owns Rust-only messages and requires
  `slint = false`. Stable semantic keys remain unique across both registries;
  English text is source copy, not an id.
- `i18n/locales/<locale>/LC_MESSAGES/usher.po` translates Slint-visible messages;
  the adjacent `usher-rust.po` translates Rust-only messages. Translators edit
  these two PO files for an existing non-source locale. Source English comes
  directly from the registries and has no PO file.
- `crates/usher-i18n-build/` owns catalog validation, Rust generation, and Slint
  bundle preparation. It has no embedded catalog or build script; callers pass
  their current repository root. It also returns validated locale metadata for
  the Settings language pickers.
- `crates/usher-i18n/` builds the merged runtime catalog through that helper,
  resolves locale aliases, and stores the process-wide Rust catalog selection.
  UI build scripts depend directly on the catalog-free helper.
- `crates/usher-ui-build/` owns the five static UI roots' Slint Cargo integration (including the optional playground).
  It uses the public Slint build API, preserves real source/resource and environment
  dependencies, and excludes this invocation's generated `OUT_DIR` outputs from
  rerun inputs. It does not own catalogs or runtime language state.
- `src/i18n.rs` is the application-owned Slint facade. It updates generated UI
  models and calls `slint::select_bundled_translation` on the event loop.
- `AppState::on_set_language` in `src/lib.rs` applies the locale, then invokes
  feature projection refreshes before scheduling preference persistence.
  Adding dynamic copy requires inspecting that feature's `sync_language` path;
  compiling an `I18n` property alone does not refresh Rust-captured strings.
- Embedded Window-rooted factory products use the renderer of their actual
  host. Settings `src/settings_page.rs::create_page`, the static playground's
  `src/ui_components/mod.rs::create_page`, and PR Review's
  `src/workflow/pr_review/ui.rs::view` use `new_with_existing_window` and
  immediately restore MainWindow's shell root before binding callbacks, even
  when construction returns an error. A standalone hidden WindowAdapter cannot
  release the host's cached text when conditional/model children are destroyed.
- Build/catalog regression owners are `crates/usher-i18n-build/`,
  `crates/usher-i18n/build.rs`, root `build.rs`,
  `scripts/check-i18n.sh`, `scripts/tests/test_i18n_build_paths.py`,
  `scripts/tests/test_root_i18n_build_paths.py`, and the
  application-linked shared-root test in `src/i18n.rs`.

语言切换的应用入口为 `src/lib.rs` 中 `AppState::on_set_language`；动态文案必须配套
核对 Feature 的 `sync_language`。仅编译 catalog 不能验证 Rust 已保存的展示字符串。
Window 根的嵌入式 factory 必须使用实际宿主 renderer；Settings、静态演练场和 PR Review 使用
共享窗口构造器，并在绑定前立即恢复 MainWindow 根，错误结果也先恢复。独立隐藏
WindowAdapter 无法在条件/model 子树销毁时清理宿主的文本缓存。

## Invariants / 不变量

1. Settings persists only `auto` or a canonical locale id. `auto` resolves the
   current system locale; an unknown locale falls back through the manifest.
2. Locale matching is case-insensitive and treats `_` and `-` as equivalent.
   Parent fallback is used only when that parent is explicitly registered as an
   id or alias, so adding regional variants never changes selection by accident.
3. Language switching is immediate and does not restart the application.
4. Language names are displayed in their native language. Only the synthetic
   `System default` option is translated.
   Locale-owned compact-control typography corrections are declared as bounded
   numeric metadata in the same manifest; UI components never branch on a
   locale id.
5. Rust consumes both registry/PO scopes; Slint consumes the Slint-visible
   scope. Shared keys use the same source and translations. Missing optional
   translations fall back to source text. The runtime catalog enforces each
   locale's manifest coverage threshold across the combined message set,
   preserving the aggregate coverage contract across the source split.
6. Handwritten `@tr()` calls are forbidden in `ui/`. The build generates one
   typed `I18n` global from `messages.toml`.
7. `MainWindow`, Settings, Messages, and the optional static UI Components
   playground are separately generated Slint roots. Slint shares the bundled
   language list and selected language index within the runtime context; each
   generated module owns its own message arrays and references them directly.
   The compiler may prune unused messages, so generated message indexes need
   not match across modules. Every root must still receive the same complete
   Slint-visible registry and locale inputs, with identical language ordering.
   A factory-local bundle or partial catalog is invalid even if it compiles.
   With `live-preview,ui-components`, the playground is part of the integrated
   interpreter root and its optional static package skips Slint generation.
8. User-facing Rust text is translated at the presentation boundary. Domain
   errors retain structured kinds and technical context; long-lived state stores
   semantic keys, structured values, or `LocalizedText`, never an already
   translated `String`. Logs remain English and must not be translated.
9. Locale support is open-ended and data-driven. Adding a target locale must
   not add a language enum, locale-specific branch, Settings option, or build
   script case; the manifest and that locale's two independent PO catalogs are the
   complete extension interface.
10. Named placeholders such as `{version}` and `{code}` are the interpolation
    contract. A translation may reorder them but must preserve the source name
    set exactly; positional placeholders and locale-specific argument branches
    are forbidden.
11. Product and engineering terms remain English across locales: GitHub,
    GitLab, Gitee, Provider, AI Agent, AI Review, Pull Request, PR, Review,
    Commit, Branch, Tag, Diff, SHA, Workflow, Job, Terminal, Git, Markdown,
    Token, API, and URL. Translations adapt surrounding prose, not these terms.
12. Provider, PTY, filesystem, protocol, and remote-payload details are logged
    but are not exposed as UI copy. The UI receives a stable semantic error kind
    and resolves a friendly catalog message at its presentation boundary.
13. Persisted Chat history may contain an application-authored error rendered
    in any registered locale. The Chat renderer may identify that exact catalog
    value across all packaged locales and re-project its semantic key in the
    active locale. It must never classify arbitrary Provider content this way.
14. The production Slint hardcoding gate covers `text`, Tooltip,
   `placeholder-text`, and accessible labels/descriptions. Its exclusions are
   limited to development showcases/fixtures and an exact, reviewed allowlist
   for brands, compact identifiers, and measurement/example sentinels.
15. Messages consumed only by Rust belong in `rust-messages.toml` with
    `slint = false` and use `usher-rust.po`. They remain in every merged Rust
    catalog and aggregate coverage check, while UI build scripts neither read
    nor watch these files. `messages.toml` accepts only Slint-visible messages.
    Duplicate keys and Slint property-name collisions are rejected across both
    scopes; moving a key between scopes requires moving its PO entry as well.
16. Persisted Inbox rows normally preserve publisher copy verbatim. For a
    narrowly allowlisted application-authored message family, the presentation
    bridge may recognize an exact packaged-catalog value together with its
    application channel, source, and category, then re-project that semantic
    key in the active locale. Remote, user-authored, and unrecognized copy must
    never be classified this way.
17. A UI change is incomplete unless all affected copy supports every packaged
    locale. Slint uses generated `I18n` properties; Rust-owned models retain
    semantic identifiers and rebuild translated labels when the locale changes.
    Tests must cover the source locale and at least one packaged non-source locale,
    including already-mounted dynamic rows, dialogs, menus, and overlays.
    任何 UI 改动只有在所有受影响文案支持全部内置语言后才算完成。Slint 使用生成的
    `I18n` property；Rust model 保留语义标识，并在语言变化时重新生成翻译标签。
    测试必须覆盖源语言及至少一种内置非源语言，包括已挂载的动态行、弹窗、菜单和浮层。

## Changing user-facing copy / 修改用户可见文案

1. Add or update a stable key in `i18n/messages.toml` for Slint-visible copy, or
   `i18n/rust-messages.toml` with `slint = false` for Rust-only copy. Update its
   `msgctxt`, source `msgid` and translation in the corresponding `usher.po` or
   `usher-rust.po` for every packaged non-source locale, retaining the exact
   named-placeholder set. Rust may also use keys from the Slint-visible scope.
2. Slint binds the generated `I18n` property directly. Rust retains a semantic
   key/arguments or `LocalizedText` and resolves at projection time; ensure the
   mounted feature's locale-refresh path reprojects existing values.
3. Run the catalog and application-linked checks below, then inspect the
   affected route with source and non-source locales without remounting.

Inline `slint::slint!` test roots must also compile the complete bundle. Root
`build.rs` exports `SLINT_BUNDLE_TRANSLATIONS` for those harnesses; importing
the generated `@i18n` global alone leaves `@tr` on the source/gettext path.
Tests must advance a UI turn before checking deferred `changed` effects, while
keeping assertions on the same mounted nodes for locale-only updates.

修改文案时按消费者选择 registry：Slint 可见文案进入 `messages.toml` / `usher.po`，
仅 Rust 使用的文案进入 `rust-messages.toml` / `usher-rust.po` 并声明 `slint = false`。
同时更新所有内置非源语言的对应 PO（含 source msgid、译文和同名占位符）；
Slint 直接绑定生成 property，Rust 保留 key/参数或 `LocalizedText`。已挂载动态展示
必须通过 Feature 刷新路径重投影，再执行 catalog、应用链接与语言切换验收。
内联 `slint::slint!` 测试根也必须编译完整 bundle；根 `build.rs` 通过
`SLINT_BUNDLE_TRANSLATIONS` 传入，单独 import `@i18n` 不会使 `@tr` 自动打包翻译。
验证延迟 `changed` 效果前推进一个 UI turn；仅切语言时仍须断言原挂载节点即时更新。

## Build invalidation / 构建失效边界

MainWindow, Settings, Messages, PR Review, the optional static playground, and root inline-test
build scripts use `usher-i18n-build` without depending on the runtime `usher-i18n` catalog. For
catalog inputs they watch `manifest.toml`, `messages.toml` and each registered
non-source locale's `usher.po`; they must not watch Rust-only inputs or shared
source directories containing them.
The runtime catalog build watches both registries and both PO scopes. The
Settings picker reads the prepared bundle's validated `locales` metadata.

A Rust-only source or translation edit therefore updates the application-linked
Rust catalog without invalidating unrelated UI compilation units. A manifest
change, Slint-visible key/source change, or `usher.po` edit still invalidates all
roots: each root needs the same complete ordered Slint bundle. This boundary
does not change runtime locale selection, presentation APIs, or native behavior.
Build-time gains require the batch's controlled A/B evidence.

MainWindow、Settings、Messages、PR Review、可选静态演练场及根包内联测试的构建脚本直接使用无内嵌 catalog、
无自身 build script 的 `usher-i18n-build`，不依赖运行时 `usher-i18n` catalog。
对于 catalog 输入，它们只监听 `manifest.toml`、`messages.toml` 与内置非源语言的
`usher.po`，禁止监听 Rust-only 输入或包含它们的共享源目录。
运行时构建合并两份 registry/PO 并统一校验覆盖率；
Settings picker 从 prepared bundle 的 `locales` 读取已校验的语言元数据。
Rust-only 文案修改不使无关 UI 编译单元失效；manifest、Slint 可见语义 key/源文案
或译文变化仍须使所有根失效，以保持完整 catalog 的索引一致。运行时 API、locale
语义及原生行为保持既有契约；构建耗时收益以专项受控 A/B 为准。

The five static roots (when the playground is enabled) compile through `usher-ui-build`. Generated translation
directories and generated `i18n.slint` beneath the current `OUT_DIR` are outputs;
they must not cause a second build after successful generation. Original
catalogs/locales, imported Slint, assets and the supported Slint environment
variables remain watched. Callers generating bundles must register their original
inputs through the catalog helper. Validate initial generation and real source,
translation, locale and environment changes, each followed by an unchanged build;
also retain unrelated-input controls and generated-code equivalence.

包含可选静态演练场时，五个静态 UI 根通过 `usher-ui-build` 编译。当前 `OUT_DIR` 中的翻译目录与生成
`i18n.slint` 是输出，成功生成后不得让下一次无修改构建额外重跑。原始 catalog/locale、
导入 Slint、资源及支持的 Slint 环境变量仍须被监听；生成 bundle 的调用方通过 catalog
helper 登记原始输入。验收覆盖首次生成、真实源/翻译/语言/环境修改及各自之后的无修改
构建，并保留无关输入对照和生成代码等价检查。

The [2026-10-16 build integration validation（归档：docs/validation/mainwindow-codegen-20261016/README.md）](../local-archives.md#validation-experiments-20261016)
records root/library Cargo fixtures, the four actual build branches, unchanged
freshness and an offline English/zh-CN native smoke; it is not full-route visual
or Release/runtime-performance acceptance.
本轮[构建集成验证（归档：docs/validation/mainwindow-codegen-20261016/README.md）](../local-archives.md#validation-experiments-20261016)覆盖 root/library
Cargo 正反例、四个实际构建分支、无修改缓存命中及中英文原生离线 smoke，不代表全路由
视觉验收或 Release/运行时性能结论。

The PR Review static product uses the same complete bundle and catalog-free
helper. `live-preview` instead selects the integrated MainWindow graph and skips
that static product; `dev-shell` keeps the protocol and bundle while replacing
the heavy page. The shared-root test resolves the actual PR owner in either mode
and checks its sentinel plus PR global copy during locale switches. The build-path
fixtures reuse all five compiled UI build scripts against tiny Slint documents,
compare full catalogs and language ordering, exclude corrupted Rust-only inputs
from reads/watches, and retain a Slint-visible source-edit control. These are
catalog/build-boundary checks, not native text-painting or performance acceptance.

PR Review 静态产品使用相同完整语言包和无 catalog 构建 helper；实时预览选择主窗口
集成图并跳过静态产品，dev-shell 保留协议/语言包而替换重页面。共享 root 测试在两种
模式下取得实际 PR owner，切换语言时检查 sentinel 及 PR global 文案。构建路径夹具对
五个已编译 UI build script 使用极小 Slint 文档，比较完整 catalog/语言顺序，验证损坏的
Rust-only 输入不被读取或监听，并保留 Slint 可见文案修改的正例。这些不能替代原生绘制
或性能验收；完整边界见 [PR Review UI](pr-review-ui.md)。

## Compatibility and known gaps / 兼容边界与已知缺口

Legacy Chat JSONL stores assistant content as text. `src/chat/renderer.rs`
recognizes a finite set of exact application-error catalog values across packaged
locales and reprojects them; `chat::sync_language` re-renders mounted messages.
Unrecognized/older copy remains verbatim. This compatibility mechanism is not a
general semantic-error schema or permission to persist newly introduced translated
state. See [Chat](chat.md).

The open status-bar detail popup retains a semantic popup identity and binds its
title/content to the current catalog and feature state. Shortcut initialization
and download progress retain typed phases/values in Rust and re-project through
their `sync_language` hooks. See [Status bar](status-bar.md) for mounted-popup
regressions. Full-route visual QA remains required; shared-root catalog tests
only prove the covered roots and properties.

旧 Chat JSONL 保存 assistant 文本；`src/chat/renderer.rs` 只对有限集合、精确匹配的
内置应用错误跨语言重译，`chat::sync_language` 会重绘已挂载消息。未知/更旧文案原样
保留；此兼容机制不代表通用语义错误 Schema，也不允许新增状态持久化译文，见
[Chat](chat.md)。已展开的状态栏详情保留语义 popup 身份，标题/正文绑定当前 catalog
与功能状态；快捷键初始化、下载进度在 Rust 保留强类型阶段/数值，通过各自
`sync_language` 即时重投影。已挂载 popup 回归见 [Status bar](status-bar.md)。
共享根 catalog 测试不能代替全路由视觉验收。

## Adding a locale / 新增语言

Catalog build scripts resolve `CARGO_MANIFEST_DIR` from the current Cargo
invocation. They must not embed the checkout that compiled the build-script
executable: a shared target directory can reuse that executable in another
checkout. The application-linked Rust catalog must resolve newly added keys in
the source and packaged non-source languages; checking only the i18n crate's
own compilation does not verify the application's dependency graph.

Catalog 构建脚本从当前 Cargo 调用读取 `CARGO_MANIFEST_DIR`，不得把编译脚本
可执行文件时的工作区路径固化进去，因为共享 target 目录可能在另一工作区复用
该可执行文件。应用实际链接的 Rust catalog 必须能解析源语言及内置非源语言的
新增 key；仅检查 i18n crate 自身的编译不能验证应用依赖图。

Hook notifications use versioned, feature-owned semantic metadata across Inbox,
Banner and native delivery. Their stored title contains the user-owned name and
their body is empty; presentation derives application copy from metadata. This
applies only to trusted application/Hook records with a recognized version.
Legacy notifications are not guessed from text. See [Hooks](hooks.md).

1. Add one locale entry to `i18n/manifest.toml`, including its native name,
   intentional aliases, and any measured compact-control typography correction.
2. Add `i18n/locales/<locale>/LC_MESSAGES/usher.po` for keys from `messages.toml`
   and adjacent `usher-rust.po` for keys from `rust-messages.toml`, using stable
   `msgctxt` keys. The source locale `en` uses registry text and needs no PO.
3. Set a realistic `minimum_coverage`; release locales should use `1.0`.
4. Run `scripts/check-i18n.sh`, then build the full root UI.

No Settings control, Rust locale match, UI model, or build-script branch should
change when adding a locale.

## Failure behavior / 失败行为

- Duplicate keys or property-name collisions within/across scopes, misplaced
  `slint` flags, duplicate aliases, stale or cross-scope PO
  contexts, source-text drift, placeholder drift, parse errors, and insufficient
  coverage fail the build.
- An unavailable persisted locale resolves to the configured fallback without
  corrupting Settings.
- Failure to select a catalog already validated into the binary is logged as an
  application error; the previous language remains selected and the preference
  is not saved.

## Regression checklist / 回归清单

- Run `scripts/check-i18n.sh`.
- Run `cargo test -p usher-i18n-build --locked` for scope isolation, malformed
  inputs, aggregate coverage and bundle-preparation controls.
- Run `cargo test -p usher-i18n --locked`.
- Run `python3 -m unittest scripts.tests.test_i18n_build_paths` after building
  the i18n crate. Verify one build-script executable reads and watches each of
  two isolated checkout catalogs at invocation time, including both registry/PO
  scopes and their exact watched paths.
- Run `python3 -m unittest scripts.tests.test_root_i18n_build_paths` after a root
  build. Reuse that executable in two checkout paths and verify each receives
  its own complete inline-test bundle and exported translation path. Verify
  differing locale manifests/source copy are read from the current checkout,
  and changing Rust-only inputs preserves the Slint bundle and watched paths.
- Record a controlled `ui-components` A/B for Rust-only registry and translation
  edits. Inspect Cargo freshness for all enabled UI crates (five with the static
  playground); retain a genuine Slint-visible edit as the control that still
  invalidates the shared bundle.
- Verify the shared-bundle test creates MainWindow, Settings, Messages, PR Review
  and the enabled static playground roots and reads the same translated sentinel from
  each, switching locale on the same mounted roots.
- For Settings, the static playground and PR Review, verify actual host-adapter
  identity and immediate MainWindow root restoration through their creation owners.
  Retain the standalone `new()` constructor as a negative fixture: its adapter
  must differ from the host. Repeat creation/drop and real factory route reentry
  while asserting the shell item-tree identity remains unchanged.
  Repeat locale/model updates and route cycles in the native app, checking
  painted labels and icons as well as catalog/accessible values. A renderer
  cache ownership failure must not be patched by changing correct PO entries.
  The headless testing backend does not use the production text-layout cache;
  successful property/accessible-label tests alone do not prove native repaint.
- Switch `System default`, `English`, and one non-source locale in Settings;
  verify immediate repaint and restart persistence.
- Check compact and regular Settings layouts with the longest shipped labels.
- Visit every production route in each packaged locale; verify Tooltip copy,
  empty/loading/error states, Toast defaults, and any already-mounted dynamic
  state after switching language.
- For UI backed by Rust models, switch locale without remounting the page and
  verify visible rows, current dialog values, open menus, and accessible labels
  are re-projected rather than retaining the previous language.
- Run the standard repository formatting, check, unit-test, and diff gates.
