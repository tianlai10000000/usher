# Internationalization / 国际化

## Scope / 范围

This specification owns packaged UI locales, locale selection and fallback,
Slint translation bundles, Rust-authored user-facing copy, and translation
maintenance gates. It does not translate logs, protocol values, provider
identifiers, file paths, model names, or remote server payloads.

本文负责内置 UI 语言、语言选择与回退、Slint 翻译 bundle、Rust 生成的用户可见
文案，以及翻译维护门禁。日志、协议值、Provider 标识、文件路径、模型名称和远端
服务返回内容不属于翻译范围。

## Ownership / 职责

- `i18n/manifest.toml` is the locale registry. It owns canonical BCP-47-like
  ids, native display names, aliases, and per-locale coverage floors.
- `i18n/messages.toml` is the source-language message registry. Stable semantic
  keys are the application contract; English text is source copy, not an id.
- `i18n/locales/<locale>/LC_MESSAGES/usher.po` is the only file translators
  edit for an existing locale.
- `crates/usher-i18n/` validates and compiles catalogs, resolves locale aliases,
  stores the process-wide Rust catalog selection, and prepares identical Slint
  bundles for every UI compilation unit.
- `src/i18n.rs` is the application-owned Slint facade. It updates generated UI
  models and calls `slint::select_bundled_translation` on the event loop.

## Invariants / 不变量

1. Settings persists only `auto` or a canonical locale id. `auto` resolves the
   current system locale; an unknown locale falls back through the manifest.
2. Locale matching is case-insensitive and treats `_` and `-` as equivalent.
   Parent fallback is used only when that parent is explicitly registered as an
   id or alias, so adding regional variants never changes selection by accident.
3. Language switching is immediate and does not restart the application.
4. Language names are displayed in their native language. Only the synthetic
   `System default` option is translated.
   Locale-owned compact-control typography corrections are declared as bounded
   numeric metadata in the same manifest; UI components never branch on a
   locale id.
5. Rust and Slint consume the same semantic keys and the same PO catalogs.
   Missing optional translations fall back to source text; shipped coverage
   must still satisfy each locale's manifest threshold.
6. Handwritten `@tr()` calls are forbidden in `ui/`. The build generates one
   typed `I18n` global from `messages.toml`.
7. `MainWindow`, Settings, and Messages are separately generated Slint roots
   but Slint stores one translation bundle per runtime context. Every root must
   therefore compile the complete generated catalog with identical ordering.
   A factory-local bundle or partial catalog is invalid even if it compiles.
8. User-facing Rust text is translated at the presentation boundary. Domain
   errors retain structured kinds and technical context; long-lived state stores
   semantic keys, structured values, or `LocalizedText`, never an already
   translated `String`. Logs remain English and must not be translated.
9. Locale support is open-ended and data-driven. Adding a target locale must
   not add a language enum, locale-specific branch, Settings option, or build
   script case; the manifest and that locale's independent PO file are the
   complete extension interface.
10. Named placeholders such as `{version}` and `{code}` are the interpolation
    contract. A translation may reorder them but must preserve the source name
    set exactly; positional placeholders and locale-specific argument branches
    are forbidden.
11. Product and engineering terms remain English across locales: GitHub,
    GitLab, Gitee, Provider, AI Agent, AI Review, Pull Request, PR, Review,
    Commit, Branch, Tag, Diff, SHA, Workflow, Job, Terminal, Git, Markdown,
    Token, API, and URL. Translations adapt surrounding prose, not these terms.
12. Provider, PTY, filesystem, protocol, and remote-payload details are logged
    but are not exposed as UI copy. The UI receives a stable semantic error kind
    and resolves a friendly catalog message at its presentation boundary.
13. Persisted Chat history may contain an application-authored error rendered
    in any registered locale. The Chat renderer may identify that exact catalog
    value across all packaged locales and re-project its semantic key in the
    active locale. It must never classify arbitrary Provider content this way.
14. The production Slint hardcoding gate covers `text`, Tooltip,
   `placeholder-text`, and accessible labels/descriptions. Its exclusions are
   limited to development showcases/fixtures and an exact, reviewed allowlist
   for brands, compact identifiers, and measurement/example sentinels.
15. Messages consumed only by Rust set `slint = false` in `messages.toml`.
    They remain in every Rust/PO catalog and coverage check but are omitted from
    generated Slint properties, so platform-only copy cannot perturb live UI
    translation indexes.
16. Persisted Inbox rows normally preserve publisher copy verbatim. For a
    narrowly allowlisted application-authored message family, the presentation
    bridge may recognize an exact packaged-catalog value together with its
    application channel, source, and category, then re-project that semantic
    key in the active locale. Remote, user-authored, and unrecognized copy must
    never be classified this way.

## Adding a locale / 新增语言

1. Add one locale entry to `i18n/manifest.toml`, including its native name,
   intentional aliases, and any measured compact-control typography correction.
2. Add `i18n/locales/<locale>/LC_MESSAGES/usher.po` using the stable `msgctxt`
   keys from `messages.toml`.
3. Set a realistic `minimum_coverage`; release locales should use `1.0`.
4. Run `scripts/check-i18n.sh`, then build the full root UI.

No Settings control, Rust locale match, UI model, or build-script branch should
change when adding a locale.

## Failure behavior / 失败行为

- Duplicate keys, property-name collisions, duplicate aliases, stale PO
  contexts, source-text drift, placeholder drift, parse errors, and insufficient
  coverage fail the build.
- An unavailable persisted locale resolves to the configured fallback without
  corrupting Settings.
- Failure to select a catalog already validated into the binary is logged as an
  application error; the previous language remains selected and the preference
  is not saved.

## Regression checklist / 回归清单

- Run `scripts/check-i18n.sh`.
- Run `cargo test -p usher-i18n --locked`.
- Verify the shared-bundle test creates MainWindow, Settings, and Messages roots
  and reads the same translated sentinel from each.
- Switch `System default`, `English`, and one non-source locale in Settings;
  verify immediate repaint and restart persistence.
- Check compact and regular Settings layouts with the longest shipped labels.
- Visit every production route in each packaged locale; verify Tooltip copy,
  empty/loading/error states, Toast defaults, and any already-mounted dynamic
  state after switching language.
- Run the standard repository formatting, check, unit-test, and diff gates.
