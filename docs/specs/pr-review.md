# Pull request workflow / Pull Request 工作流

## Scope / 范围

This specification is the portable contract for the current pull-request capability: project-scoped counts, the paginated PR/MR list, the full-window review workspace, diff/source enrichment, remote review, merge, and capability-gated revert commands.

本文是当前 Pull Request 能力的可迁移契约：项目级计数、分页 PR/MR 列表、全窗口审核工作区、diff/源码补全、远端评审、合并与按能力开放的回退命令。

The Slint presentation is application-owned: reusable PR/Review visual
components live in `ui/components/workflow/` or `ui/components/pr_review/`
and every visual symbol uses the `GitHub` prefix. The PR collection follows a
Primer DataTable/Box pattern with ActionMenu filters, shared Button/IconButton
actions, Blankslate empty/error states, and pagination outside the bordered
list. The review route keeps public `@material` ListView/ScrollView only as
replaceable virtualization/scroll behavior; typography, colors, controls,
TreeView-like hierarchy, diff chrome, and dialogs are owned by GitHub-prefixed
application components. Vendored Material source is read-only.

Slint 展示层归应用所有：可复用 PR/Review 视觉组件统一位于
`ui/components/workflow/` 或 `ui/components/pr_review/`，组件符号全部以
`GitHub` 开头。PR 集合遵循 Primer DataTable/Box 结构，筛选使用
ActionMenu，操作复用 Button/IconButton，空白与错误状态使用 Blankslate，
分页位于列表边框外。审核路由仅把公开 `@material` ListView/ScrollView
作为可替换的虚拟化/滚动行为；排版、颜色、控件、TreeView 式层级、diff
外壳及 Dialog 均由 GitHub 前缀的应用组件负责。vendored Material 源码只读。

## Product boundary / 产品边界

The current product supports the following workflow:

1. A selected project optionally displays counts of open changes targeting `fat`, `uat`, and `prod`.
2. The PR tab loads one page of open, closed, merged, or all changes and displays number, title, branch pair, author, and UTC+08:00 update time. The repository header keeps the alias readable before its adjacent Provider/ID labels. Wide layouts show remote and local paths on one left-aligned row that hugs each path’s ideal width (same density as the original remote-only row) with copy/reveal actions, and only share/elide when both ideals no longer fit. Below 720 px, GitHub-style compact navigation keeps identity on one row and moves both paths/actions into a trailing kebab overlay anchored by a Primer `invisible` IconButton (32×32, no border, muted hover/open fill like the PR-list overflow control); the overlay is a Primer ActionMenu (12px large radius, muted Remote/Local section labels, trailing copy/open IconButtons) mounted on the Workflow shell above the tab row (not inside the 52 px header, which sibling tabs would cover), and uses the shared dismiss-under-chrome stacking contract so outside clicks close it. The list header follows GitHub's responsive pull-request filters: Open/Closed and filter actions remain on one 48 px row; below 620 px, Assignee remains directly accessible while Reviews and Sort move into one grouped kebab menu. The menus are mutually exclusive, and switching opens the target on the first click. PR titles use the default foreground color and switch to the link accent on hover, while pagination stays centered below the card (16px gap; the footer must not sit inside the list-card border). Branch and Updated cells wrap instead of using ellipsis; each row grows with the wrapped cell height so multi-line Branch pairs are not clipped. A horizontal scrollbar appears when the list card is narrower than the table floor width.
3. Opening a row navigates to a dedicated full-window PR review route with Conversation, Commits, and Files changed tabs (Checks is intentionally excluded). The Conversation timeline includes GitHub-style activity rows for commit batches and merges in addition to description/comments/reviews; adapters map provider-native sources into the shared kinds without sharing provider rules. Commit rows under a Conversation `commits` batch and the Commits tab list both render newest→oldest (latest change first), while UTC+08:00 date grouping on Commits still places newer calendar days above older ones. The tabs keep the product's underline selection style while using upstream GitHub Primer Octicons and inline icon/label/count geometry. Overall additions, deletions, and the five-cell diffstat live at the right edge of this primary tab row rather than being duplicated in the Files changed toolbar. Commits groups entries by UTC+08:00 calendar date in one shared GitHub-style card (Primer medium 6px corner radius with real border strokes, Box-row-like ~16px/12px internal padding, and a clear gap under the date heading), shows title, author, GitHub-style commit time (`yesterday`, `last week`, or past the 30-day Primer threshold `on Mar 19` / `on Mar 19, 2025`) with an absolute-datetime tooltip, verification state, and a vertically centered short SHA, and provides a tooltip-labeled full-SHA copy button while intentionally omitting the web page's code-browse button. Files changed provides the file tree, per-file Unified or Split diff, GitHub-style file actions, immutable base/head references, filtering, folder collapse, and next/previous file navigation.
4. The Files changed toolbar can open a GitHub-style commit selector and switch between the complete PR diff and a contiguous commit range. The selector reuses the newest→oldest Commits model; the controller maps selected display indices back onto the provider-neutral oldest→newest list before range selection. Provider adapters normalize commit collections from oldest to newest for that math. Selecting the chronologically first PR commit uses the PR base SHA; any later starting commit uses the preceding PR commit as the comparison base, so the first selected commit remains included. A single-commit selection adds one compact summary row to the Files changed toolbar with its title, previous/next commit navigation, author/time, short SHA, and full-SHA copy action. The summary starts exactly at the file-tree right divider, keeps its title left-aligned in the Diff region, and must not consume vertical diff space; the intentionally omitted Browse files action must not be added. Previously loaded ranges are cached for the active PR. The selected file toolbar can copy the file path, toggle between expanding all hidden lines and collapsing non-diff lines, or switch between the diff and the complete immutable file source. Expanding all lines reconstructs through source EOF, including trailing source after the final diff hunk. Hidden diff context can also be expanded in bounded 20-line increments. The in-diff Ctrl/Cmd+F search must recompute after every replacement of the selected file's line model, including same-file context expansion, without turning that content refresh into a viewport reset.
5. `Review changes` opens one GitHub-style dialog for Comment, Approve, or Request changes. The selected provider capability controls which choices are enabled, and submission writes to the remote provider. Every PR dialog surface is horizontally and vertically centered against the complete application window, independent of the docked sidebar width; its backdrop is continuous across the sidebar boundary and through the macOS native-title-bar inset without a one-pixel seam. AppKit's close/minimize/zoom traffic lights remain clickable above it, while the application-owned sidebar/back/forward title-bar accessories are shielded from hover, Tooltip, and click input. The Conversation tab also has a GitHub-style plain-text comment composer at the bottom (`Write` + green `Comment`). GitHub Conversation comments post as issue comments so they remain available on open, closed, and merged PRs; Approve and Request changes stay open-PR only. Gitee Conversation Comment continues to use the provider note/comment endpoint with the same open/closed/merged availability when a token is configured.
6. Review submission never merges automatically. After a successful review the controller refreshes remote action state; only a server-reported mergeable PR enables `Merge pull request`, whose confirmation dialog offers only provider/repository-supported methods and optional source-branch deletion. A successful review or merge invalidates the cached Conversation timeline and reloads it immediately when Conversation is the active tab, so remote review and merged activity are visible without switching tabs. A successful merge also invalidates the retained PR list; returning to the list reloads page one of the active state/filter and its state totals, so the merged request is absent from Open.
7. A merged or closed PR hides header Review and Merge controls. The Conversation composer stays enabled when provider credentials are configured, matching GitHub's timeline comment box. When the adapter reports a safe server-side revert capability on a merged request, the header exposes a visible secondary revert button and a provider-specific confirmation. GitHub creates a separate revert PR. Gitee Enterprise writes a revert commit directly to the target branch only when the PR has a merge/squash commit and `GET /projects/:id/repository/commits/:sha/refs` reports both `merge_commit_by_pr=true` and `can_revert=true`; rebase and fast-forward merges remain unavailable. Public Gitee and GitLab do not expose this command.

Close/reopen, inline draft reviews, merge queues, and auto-merge are not part of the current command set.

当前产品支持以下以只读为主的流程：

1. 选中项目后，可选显示目标为 `fat`、`uat`、`prod` 的 open 变更数量。
2. PR Tab 加载 open、closed、merged 或 all 的一页变更，显示编号、标题、分支对、作者和东八区更新时间。仓库页头优先保证别名可读，Provider/ID 标签紧跟别名。宽屏在同一行左对齐显示远程与本地路径，各自按理想宽度贴合（与原先仅远程一行的密度一致），并提供复制/打开操作；两者理想宽度放不下时才共享剩余宽度并省略。低于 720px 时按 GitHub 紧凑导航只保留一行身份信息，把路径与操作收进尾部 kebab 浮层；触发器为 Primer `invisible` IconButton（32×32、无边框、muted hover/展开底色，与 PR 列表 overflow 一致），浮层为 Primer ActionMenu（12px large 圆角、Remote/Local 分区弱化标题、尾部复制/打开 IconButton），并遵循 dismiss 垫在交互控件之下的堆叠约定，点击外部关闭，且绘制在 Workflow Tab 行之上。列表页头严格遵循 GitHub 响应式 PR 筛选：Open/Closed 与筛选操作保持在同一个 48px 行；低于 620px 时直接保留 Assignee，将 Reviews 与 Sort 合并进一个分组 kebab 菜单。菜单互斥，第一次点击即可切换目标。PR 标题默认使用正文前景色，hover 时切换为链接强调色；分页栏在卡片下方保持居中（与卡片间隔 16px，不得落在列表卡片边框内部）。Branch 与 Updated 列换行完整显示，不得使用省略号；行高随换行内容增高，避免多行 Branch 被裁切；列表卡片窄于表宽下限时出现横向滚动条，而不是丢列。
3. 打开某一行后导航到独立的全窗口 PR 审核路由，提供 Conversation、Commits、Files changed Tab（明确不包含 Checks）。Conversation 时间线除描述/评论/Review 外，还包含 GitHub 风格的批量提交与合并活动行；各 adapter 把 Provider 原生数据映射到共享 kind，不共享彼此判定规则。Conversation 中 `commits` 批次下的提交行与 Commits Tab 列表均按从新到旧展示（最新变更在前），Commits 按东八区自然日分组时较新的日期仍排在较旧日期之上。Tab 保留产品的下划线选中样式，但使用 GitHub Primer 官方 Octicon 及同行的图标/文字/计数布局。全局增删行数与五格 diffstat 放在主 Tab 行右侧，不再重复显示在 Files changed 工具栏。Commits 按东八区自然日分组到同一个 GitHub 风格卡片中（Primer medium 6px 圆角使用真正的 border 描边，行内约 16px/12px 内边距，日期标题与卡片之间留出空隙），显示标题、作者、GitHub 风格相对提交时间（如 `yesterday`、`5 days ago`、`last week`）及绝对时间 Tooltip、签名状态和垂直居中的短 SHA；每行提供带 Tooltip 的完整 SHA 复制按钮，但明确不提供网页最右侧的代码浏览按钮。Files changed 展示文件树、按文件的 Unified 或 Split diff、GitHub 风格文件操作、固定的 base/head 引用、筛选、目录折叠与上/下一个文件导航。
4. Files changed 工具栏可打开 GitHub 风格的 commit 选择器，在完整 PR Diff 与连续 commit 范围之间切换。选择器复用 Commits 的从新到旧展示 model；控制器在计算范围前把选中的展示索引映射回 Provider-neutral 的从旧到新列表。Provider adapter 仍把 commit 集合归一为从旧到新以供该计算使用。范围从时间线上第一个 PR commit 开始时使用 PR base SHA；从后续 commit 开始时使用其前一个 PR commit 作为比较基准，因此不会漏掉首个选中 commit。单 commit 状态把标题、前后 commit 导航、作者/时间、短 SHA 和完整 SHA 复制操作压缩成一行；该行从文件树右侧分隔线的位置准确起始，标题在 Diff 区域内左对齐，不额外占用垂直空间；明确不加入 Browse files。已加载范围在当前 PR 内缓存。选中文件工具栏支持复制文件路径、在“展开全部隐藏行”和“收起非 diff 行”之间切换，以及在 diff 与固定提交的完整文件源码之间切换；“展开全部”必须重建到源文件 EOF，包括最后一个 diff hunk 之后的尾部源码。方向展开按 GitHub 登录后的新版 `/changes/{commit}` 行为每次补充 21 个主侧源码行。Diff 内 Ctrl/Cmd+F 搜索必须在选中文件的行 model 每次被替换后重新计算，包括同一文件内的上下文展开；该内容刷新不得被当作 viewport 重置。
5. `Review changes` 使用一个 GitHub 风格弹窗承载 Comment、Approve、Request changes；Provider 能力决定选项是否可用，提交会写入远端。所有 PR 弹窗表面必须相对完整应用窗口水平、垂直居中，不受固定侧栏宽度影响；遮罩跨侧栏边界连续绘制并延伸覆盖 macOS 原生标题栏 inset，不得出现 1px 接缝。AppKit 的关闭/最小化/缩放交通灯保持在遮罩之上且可点击，应用自有的侧栏/后退/前进标题栏附件位于遮罩之下，遮罩显示期间不得响应 Hover、Tooltip 或点击。Conversation Tab 底部另有 GitHub 风格纯文本评论框（`Write` + 绿色 `Comment`）。GitHub Conversation 评论按 issue comment 写入，因此在 open、closed、merged 状态下仍可用；Approve / Request changes 仅对未关闭 PR 开放。Gitee Conversation Comment 继续走 note/comment 接口，在已配置 Token 时同样对 open/closed/merged 可用。
6. 评审成功后不会自动合并。控制器会刷新远端 action state；只有服务端报告可合并时才启用 `Merge pull request`，确认弹窗只列出 Provider/仓库允许的策略，并可选择删除源分支。Review 或 merge 成功后必须使 Conversation 时间线缓存失效；如果当前正处于 Conversation Tab，则立即重新加载，使远端 Review 与 merged 活动无需切换 Tab 即可出现。Merge 成功还必须使保留的 PR 列表失效；返回列表时重新加载当前状态/筛选的第一页及状态总数，确保已合并请求不再出现在 Open 列表中。
7. PR 已合并或已关闭后隐藏页头 Review 与 Merge 控件。在已配置 Provider 凭据时，Conversation 评论框保持可用，与 GitHub 时间线评论行为一致。只有 adapter 报告安全的服务端回退能力时，已合并请求的页头才显示明确可见的次级回退按钮，并展示 Provider 专属确认说明。GitHub 创建独立的反向 PR；Gitee 企业版仅在 PR 存在 merge/squash commit，且 `GET /projects/:id/repository/commits/:sha/refs` 同时返回 `merge_commit_by_pr=true` 与 `can_revert=true` 时，直接向目标分支写入回退提交；rebase 和 fast-forward 合并保持不可用。Gitee 公有版与 GitLab 不开放该命令。

当前命令集不包含关闭/重开、行内草稿评审、merge queue 或 auto-merge。

## Ownership / 职责

- `src/workflow/pr_review.rs` is the stable façade; `controller.rs` owns active requests, stale-response protection, remote action sequencing, and Slint model updates.
- `src/workflow/pr_review/cache.rs` owns bounded review/range/highlight/source caches, shared immutable diff ownership, copy-on-write expanded files, and cache memory statistics.
- `src/workflow/pr_review/avatar.rs` owns bounded, deduplicated avatar download and decoding.
- `src/workflow/pr_review/hunk.rs` owns pure immutable-source alignment, bounded hunk expansion, collapse restoration, and full-source projection.
- `src/workflow/pr_review/file_tree.rs` owns pure local file-tree construction, path/extension/manifest/viewed filtering, and folder flattening.
- `src/workflow/pr_review/diff_projection.rs` owns provider-neutral Unified/Split row projection and stable hunk scroll anchors.
- `src/workflow/pr_review/diff_model.rs` owns the read-only Slint lazy line model, its 64-row converted-data cache, and normalized-diff-to-UI row/token conversion.
- `src/workflow/pr_review/selection.rs` owns wrapped-row pointer hit testing, selectable-row rules, display-column slicing, and clipboard text projection.
- `src/workflow/pr_review/timeline.rs` owns Conversation/Commit Slint model conversion, deterministic row sizing and connection/grouping rules, plus display/chronological commit-range mapping.
- `src/git/model.rs`, `locator.rs`, and `diff.rs` own provider-neutral models, remote location, and unified-diff parsing. Provider modules own request/response handling; Gitee authentication/endpoints, decoding, Conversation/Commit normalization, readiness, and revert capability are isolated under `src/git/gitee/`.
- `src/codereview/api/` owns provider endpoint URL templates only.
- `ui/views/workflow/pr_review_workspace.slint` owns cross-region state, review layout, and user interaction. `ui/components/pr_review/shell.slint` owns public structs and shell controls; `content.slint` owns reusable file-tree and diff content controls. `ui/main.slint` mounts the workspace only for the dedicated `PrReview` route.
- `src/workflow/pr_list.rs` owns list-page selection, list request sequencing, pagination presentation, and UTC+08:00 timestamp formatting.
- `src/workflow/bindings.rs` supplies the selected project context, remote-URL copy, local-folder reveal via `src/platform/`, and the optional `fat`/`uat`/`prod` count refresh.
- `src/git/overview.rs` owns provider-neutral `fat`/`uat`/`prod` count aggregation; Provider selection, authentication, requests, and response normalization remain in the Git façade and adapters.

- `src/workflow/pr_review.rs` 是稳定 façade；`controller.rs` 负责当前请求、旧响应防护、远端 action 序列和 Slint model 更新。
- `src/workflow/pr_review/cache.rs` 负责有界 review/range/highlight/source 缓存、共享不可变 Diff 所有权、展开文件的写时复制和缓存内存统计。
- `src/workflow/pr_review/avatar.rs` 负责有界且去重的头像下载和解码。
- `src/workflow/pr_review/hunk.rs` 负责纯粹的固定源码对齐、有界 hunk 展开、收起恢复和完整源码投影。
- `src/workflow/pr_review/file_tree.rs` 负责纯本地文件树构建，以及路径、扩展名、manifest、viewed 筛选和目录扁平化。
- `src/workflow/pr_review/diff_projection.rs` 负责与 Provider 无关的 Unified/Split 行投影和稳定的 hunk 滚动锚点。
- `src/workflow/pr_review/diff_model.rs` 负责只读 Slint 惰性行 model、64 行转换缓存，以及归一化 Diff 到 UI 行/token 的转换。
- `src/workflow/pr_review/selection.rs` 负责换行后的指针命中、可选择行规则、显示列切片和剪贴板文本投影。
- `src/workflow/pr_review/timeline.rs` 负责 Conversation/Commit Slint model 转换、确定性行高和连接/分组规则，以及展示顺序与时间顺序之间的 commit range 映射。
- `src/git/model.rs`、`locator.rs`、`diff.rs` 分别负责 Provider-neutral 模型、remote 定位和 unified diff 解析。Provider 模块负责请求/响应；Gitee 的鉴权/endpoint、解码、Conversation/Commit 归一化、readiness 和 revert capability 分别隔离在 `src/git/gitee/` 下。
- `src/codereview/api/` 只负责 Provider endpoint URL 模板。
- `ui/views/workflow/pr_review_workspace.slint` 负责跨区域状态、审核布局和交互；`ui/components/pr_review/shell.slint` 负责公开 struct 与外壳控件，`content.slint` 负责可复用文件树和 Diff 内容控件；`ui/main.slint` 只在独立的 `PrReview` 路由挂载工作区。
- `src/workflow/pr_list.rs` 负责列表页选择、列表请求序列、防止旧响应覆盖、分页展示和东八区时间格式化。
- `src/workflow/bindings.rs` 提供当前项目上下文、远程 URL 复制、经 `src/platform/` 打开本地目录，以及可选的 `fat`/`uat`/`prod` 数量刷新。
- `src/git/overview.rs` 负责 Provider-neutral 的 `fat`/`uat`/`prod` 计数聚合；Provider 选择、鉴权、请求和响应归一化继续由 Git façade 与 adapter 负责。

## Portable domain contract / 可移植领域契约

An implementation in another stack should preserve these provider-neutral records rather than expose provider JSON to the UI:

| Record | Required fields | Notes |
| --- | --- | --- |
| `RepositoryContext` | project key, provider type, provider project id, remote URL | The persisted provider type must agree with the remote URL before any request is made. |
| `PullRequestPage` | items, total, `total_exact`, optional page count | The UI distinguishes an exact total from a lower bound. Page size is 10. |
| `PullRequestItem` | number, title, author, source branch, target branch, updated time, web URL | A missing branch is shown as `—`; parseable timestamps are rendered as `YYYY-MM-DD HH:MM:SS +08:00`. |
| `PullRequestDiffDetail` | files, added/removed totals, commit count, optional conversation count, base SHA, head SHA, start SHA, too-many-commits flag | The summary commit and conversation counts keep the lazy Commits/Conversation tab badges accurate before those tab payloads load. Commit-range compares leave `conversation_count` unset so they cannot wipe the PR-level badge. The SHA values are immutable source references for later context expansion. |
| `PullRequestDiffFile` | path, old path, change type, added/removed counts, lines | Change types are `new_file`, `deleted_file`, `renamed_file`, or `edit_file`. |
| `PullRequestDiffLine` | old line, new line, kind, content | Kinds are normalized to hunk/context/addition/deletion before rendering. Content is one visual source line and contains no CR/LF controls. |
| `PullRequestConversationItem` | id, kind, author, optional avatar URL/author association, body, created time, state | Description, comments, reviews, and provider system events share one chronological presentation model. GitHub review responses expand into an atomic `review_summary` + optional `review` card pair; state controls the semantic wording (`commented`, `approved these changes`, or `requested changes`) and `AUTHOR` controls the Author badge. Relative time follows GitHub Primer `<relative-time>` defaults (`yesterday`, `last week`, or past `P30D` `on Mar 19` / `on Mar 19, 2025`) and remains inline with the event text; absolute time stays in a tooltip. A merged event suppresses the redundant closed event emitted for the same merged PR. GitHub, GitLab, and both Gitee profiles normalize provider and commit-author avatar fields; the controller downloads bounded avatar payloads off the event loop, while the UI falls back to an author initial. Description/comment/review cards and the composer share the same 52 px avatar/content grid. Timeline connectors are computed between semantic neighbors: a terminal merge stops its rail, while consecutive `review_summary` + `review` pairs retain one continuous rail between the preceding card and the next summary marker. Conversation body text is decoded inside each provider adapter: GitHub/GitLab use `body`; Gitee public v5 prefers `body`; Gitee Enterprise reads `note`, then `body`/`comment`, then string `content` only (object `content` is diff context). Enterprise may also best-effort merge `/reviews` without replacing note cards. Structured activity kinds `commits` / `commit` / `merged` / `event` render GitHub-style rows. A `commits` header and its consecutive `commit` children form one atomic sorting block; the children render newest→oldest. |
| `PullRequestCommit` | SHA, title/message, author, authored time, verified | Commit signatures are shown only when the provider reports verification. |
| `PullRequestActionState` | review/revert capabilities, normalized readiness kind/detail, review state, mergeable flag, merge/revert block reasons, revert label/confirmation, allowed merge methods | The UI renders normalized capabilities and provider-specific effect text; it never infers merge or revert safety from provider names. |
| `PullRequestReviewAction` | Comment, Approve, Request changes | A provider may disable unsupported actions but labels remain consistent. |
| `PullRequestMergeMethod` | Merge, Squash, Rebase, Fast-forward | Only methods returned by the active adapter are selectable. |

其他技术栈应保留这些 Provider-neutral 记录，而不是向 UI 暴露 Provider JSON：

| 记录 | 必需字段 | 说明 |
| --- | --- | --- |

## Provider adapter contract / Provider 适配契约

Provider adapters accept a validated `RepositoryContext` and return only the domain records above. They own provider URLs, authentication headers, pagination interpretation, JSON decoding, and normalization. The UI and workflow controller neither construct URLs nor parse provider JSON.

| Provider | Read path | Review | Merge | Authentication | Tab badge counts |
| --- | --- | --- | --- | --- | --- |
| GitHub / GitHub Enterprise | issue search plus visible-row detail; PR files and contents | Comment, Approve, Request changes | repository-enabled Merge, Squash, Rebase | `Authorization: Bearer <token>` | Commits from detail `commits` or one `per_page=1` probe via Link `rel=last`; Conversation is detail `comments` plus the independently counted reviews collection, because COMMENT reviews are excluded from `comments` |
| GitLab | MR list/detail/diffs/raw file | Comment and Approve; stable REST has no Request changes command | Merge or Squash according to project `squash_option`, with HEAD SHA and optional source-branch deletion | `PRIVATE-TOKEN` when configured | Detail `commits_count` / `user_notes_count`; if commit total missing, one `per_page=1` commits probe via `X-Total` |
| Gitee public v5 | repository pull list/detail/files/contents | Comment only; v5 has no approve/request-changes endpoint | Merge, Squash | public Gitee token via `Authorization: token` | Detail `commits`/`commits_count` and `comments`/`comments_count` when present; otherwise one bounded `per_page=100` commits/comments probe (`len < per_page` is exact). Never cache full Conversation/Commits payloads for badges. |
| Gitee Enterprise v8 | project MR list/diff/file and `current_state` | Conversation Comment uses `POST /notes` with `note` and required `noteable_type: PullRequest`; Approve/Request changes use `/reviews` with `approved`/`rejected` | `restrict_merge_type`: Merge, Squash, Rebase, Fast-forward | enterprise header, `OAUTH: enabled`, separate enterprise `PRIVATE-TOKEN` | Conversation from MR detail `user_notes_count`/`notes_count`; a positive Commits count may come from diffs `commits_size` (not file-total `count`), a non-truncated embedded `commits` array, or detail. Zero is not authoritative because some deployments advertise zero before the collection is read; zero/missing first probes `with_page=true&per_page=1` for a total. A total-less response whose length equals `per_page` is ambiguous even when it is a bare array; retry the documented `with_page=false` complete collection, count it, and discard it without mounting the lazy Commits content model. |

GitHub list search provides an exact total but not `head.ref`/`base.ref`. Its extra detail requests are limited to the visible page; a failed row enrichment must not discard the page. GitLab and Gitee may report totals through headers or provider contracts; when an exact total is absent, the paginator shows a lower bound and permits the next page after a full response.

Revert is a separate capability from merge. GitHub uses the GraphQL `revertPullRequest` mutation and returns the new reverse PR. Gitee Enterprise first reloads the MR, then calls the documented commit `/refs` endpoint; only its `merge_commit_by_pr` plus `can_revert` pair permits `POST /projects/:id/repository/commits/:sha/revert` with the target `branch_name`. The latter mutates the target branch immediately and therefore uses different confirmation text. No adapter reconstructs a commit range locally.

Provider 适配层接收已验证的 `RepositoryContext`，只返回上述领域记录。它负责 Provider URL、鉴权 header、分页解释、JSON 解码和归一化；UI 和 Workflow controller 均不构造 URL，也不解析 Provider JSON。

| Provider | 读取路径 | 评审 | 合并 | 鉴权 | Tab 角标计数 |
| --- | --- | --- | --- | --- | --- |
| GitHub / GitHub Enterprise | issue search + 可见行详情、PR files、contents | Comment、Approve、Request changes | 仓库启用的 Merge、Squash、Rebase | `Authorization: Bearer <token>` | Commits 使用 detail `commits` 或一次 `per_page=1` + Link `rel=last` 探测；Conversation 为 detail `comments` 加独立计数的 reviews 集合，因为 COMMENT review 不计入 `comments` |
| GitLab | MR list/detail/diffs/raw file | Comment、Approve；稳定版 REST API 无 Request changes 命令 | 按项目 `squash_option` 提供 Merge 或 Squash，携带 HEAD SHA 并支持显式删除来源分支 | 已配置时使用 `PRIVATE-TOKEN` | Detail `commits_count` / `user_notes_count`；缺提交总数时用一次 `per_page=1` commits 探测（`X-Total`） |
| Gitee 公有 v5 | 仓库 PR list/detail/files/contents | 仅 Comment；v5 无 approve/request-changes endpoint | Merge、Squash | 公有版独立 token，使用 `Authorization: token` | Detail 有 `commits`/`commits_count`、`comments`/`comments_count` 时优先；否则各发一次有界 `per_page=100` commits/comments 探测（`len < per_page` 即为精确总数）。角标不得缓存完整 Conversation/Commits 载荷 |
| Gitee 企业 v8 | project MR list/diff/file 与 `current_state` | Conversation Comment 使用 `POST /notes` + `note` + 必填的 `noteable_type: PullRequest`；Approve/Request changes 使用 `/reviews` + `approved`/`rejected` | `restrict_merge_type` 返回的 Merge、Squash、Rebase、Fast-forward | enterprise header、`OAUTH: enabled`、企业版独立 `PRIVATE-TOKEN` | Conversation 用 MR detail 的 `user_notes_count`/`notes_count`；Commits 正数可取自 diffs 的 `commits_size`、未截断的内嵌 `commits` 数组或 detail。部分部署读取集合前会报告零，因此零值不作为可信总数；零值或缺失时先用 `with_page=true&per_page=1` 探测。无 total 且返回数量等于 `per_page` 时，即便载荷是裸数组也无法判定完整性；必须回退读取文档约定的 `with_page=false` 完整集合，计数后立即丢弃，不得挂载懒加载 Commits 内容 model。 |

GitHub 搜索列表提供准确总数，但不含 `head.ref`/`base.ref`。额外详情请求只限于当前可见页；单行补全失败不得丢弃整页。GitLab 和 Gitee 可通过 header 或 Provider 契约给出总数；没有准确总数时，分页器显示下界，并在满页响应后允许进入下一页。

回退是独立于合并的能力。GitHub 使用 GraphQL `revertPullRequest` mutation，并返回新建的反向 PR。Gitee 企业版先重新读取 MR，再调用文档定义的 commit `/refs` endpoint；只有其 `merge_commit_by_pr` 与 `can_revert` 同时为 true，才允许携带目标 `branch_name` 调用 `POST /projects/:id/repository/commits/:sha/revert`。后者会立即修改目标分支，因此确认说明必须与 GitHub 不同。任何 adapter 都不得在客户端自行重建 commit 范围。

## Execution and state flow / 执行与状态流

```text
project selected
  -> load persisted RepositoryContext off the UI thread
  -> validate provider type against remote URL
  -> fetch the selected list page through one provider adapter
  -> normalize records and apply only if list sequence is current
  -> user opens a row
  -> fetch normalized diff and remote action state with independent stale-response sequences
  -> cache one shared immutable base by project + request + whitespace mode
  -> build a local file tree and select/highlight the first file
  -> optional hunk expansion fetches immutable source once, then creates or mutates only that file's copy-on-write override
  -> collapse drops that override and exposes the provider-normalized base file without another request
  -> submit an explicit remote review command
  -> refresh action state after provider success
  -> when the provider reports mergeable, confirm one allowed method and send a separate merge command
  -> when a merged request reports can-revert, confirm the provider-specific effect and send a separate revert command
```

Every asynchronous boundary needs a monotonically increasing request sequence (separate sequences for list, conversation, commits, diff, syntax highlighting, and hunk expansion are recommended). A result may update the visible state only if its sequence, selected project, selected PR, and selected file still match. Closing the review or switching projects invalidates all in-flight work and clears review caches. Never let a stale result navigate back to the review route or replace a newer page.

```text
选择项目
  -> 在 UI 线程外读取持久化的 RepositoryContext
  -> 校验 Provider 类型与 remote URL
  -> 通过一个 Provider adapter 获取当前选中的列表页
  -> 归一化记录，且仅在列表序列仍为最新时回写
  -> 用户打开某一行
  -> 使用相互独立的旧响应序列获取归一化 diff 与远端 action state
  -> 按项目 + 请求 + 空白模式缓存一份共享且不可变的基础数据
  -> 构建本地文件树，选择并高亮第一个文件
  -> 可选的 hunk 展开只获取一次固定源码，再只创建或修改该文件的写时复制 override
  -> 收起操作删除该 override 并重新使用 Provider 归一化后的基础文件，不发起新请求
  -> 提交显式的远端评审命令
  -> Provider 成功后刷新 action state
  -> Provider 报告可合并时，确认一种允许的策略并发送独立 merge 命令
  -> 已合并请求报告可回退时，确认 Provider 专属效果并发送独立 revert 命令
```

每个异步边界都需要单调递增的请求序列（建议列表、Conversation、Commits、diff、语法高亮和 hunk 展开各自独立）。只有当序列、当前项目、当前 PR 和当前文件仍匹配时，结果才可更新可见状态。关闭审核或切换项目会使所有在途任务失效并清理审核缓存；旧结果绝不能重新导航回审核路由或覆盖新页。

## Invariants / 不变量

1. Clicking a PR list row navigates from `Route.Workflow` to the dedicated `Route.PrReview`. Both routes belong to one Workflow lifecycle domain: the Workflow component tree is unmounted, its list/root model state is retained, and Back reconstructs the PR tab without clearing heavy state. The shell does not force the navigation sidebar closed during this transition: the existing docked open/closed state is preserved, and the native title-bar toggle remains active on the review route. Conversation and Commits tab *content* load lazily on first tab selection with independent stale-response sequences; Files changed remains the initial tab and waits for neither request. Tab badge numbers update from lightweight PR/MR summary fields carried with the diff load (`commit_count`, optional `conversation_count`, and `files.length`). Badge properties are independent from lazy content-model lengths, so selecting a tab is not the normal event that first populates its badge; a successfully loaded lazy payload may only raise an inconsistent or unavailable provider summary as a compatibility fallback. When a provider omits totals, adapters may issue one bounded count probe (GitHub/GitLab/enterprise `per_page=1` with pagination meta; Gitee public `per_page=100` short-page exactness; Gitee enterprise diffs `commits_size` / embedded commits / detail `user_notes_count` or notes `note_statistics.all_note_count`). They must not prefetch full Conversation timelines or full commit lists solely to paint badges.
2. Network and project-file work runs off the Slint event loop and uses the shared HTTP/runtime modules.
3. Only the latest project/PR/reload request may update the workspace. Closing or switching projects invalidates in-flight work.
4. Provider responses are normalized before reaching UI code. The UI must not parse JSON or construct API URLs.
5. Selecting a changed file replaces only the visible line model; it does not request the diff again.
6. The Files changed toolbar exposes one GitHub-style `Diff view` popover. Unified/Split and Hide whitespace are draft choices until `Apply and reload` is pressed. Unified/Split is provider-neutral and changes only the local row projection; Split pairs each contiguous deletion/addition block and duplicates context on both sides. Its left and right panes remain equal-width even when one side is empty; long lines wrap inside their own pane and both cells share the resulting row height. Unified long lines wrap within the code column as GitHub does instead of being clipped. Diff source uses the registered SF Mono face at 13px on a 22px row; ordinary hunk rows are 28px and a between-hunk row with both directional controls is 52px. Each Split pane uses an absolutely positioned 50px center-aligned line-number gutter and a 20px change-marker column. Unified uses the same absolute Text geometry for both of its 50px number columns so old/new numbers stay symmetrically centered like GitHub `.new-diff-line-number`. Wrapped rows pin line numbers, change markers, and shorter-side content to the first visual line; neither `+` nor `-` may be vertically centered across the full wrapped-row height. Line numbers use the same plain text renderer as source code so their baselines match. Changed-line numbers use the normal foreground color; unchanged numbers remain muted. Expandable hunk controls stay inside the applicable number gutter: Unified merges the two 50px number columns into one 100px gutter and centers the Primer fold icons horizontally; Split keeps a single 50px gutter per pane. A leading gap uses Primer `fold-up-16`. A between-hunk gap larger than one 21-line page keeps separate `fold-down-16` and `fold-up-16` directional actions; when no more than one page remains, GitHub's single `unfold-16` expand-all action replaces them. Revealing the last hidden context removes the hunk separator instead of leaving an empty blue row. The SVGs are retained verbatim from the current Primer Octicons repository. Hide whitespace is enabled only when the active provider endpoint supports it (currently Gitee-compatible enterprise); unsupported providers keep the checkbox visible but disabled and must not receive a no-op whitespace request. The popover uses Primer's upward caret (45° border/fill diamonds joined to the top edge) anchored under the settings gear; when the panel is edge-clamped the caret still tracks the button.
7. Files whose normalized diff reaches the provider-neutral large-diff line or payload budget keep their normal file header and stats but do not create syntax tokens or a Slint line model by default. Their body mirrors GitHub with `Load diff` and `Large diffs are not rendered by default.`; activation shows an in-place spinner and renders only that file. Explicitly loaded files remain loaded for the active complete/range diff, and changing the commit range resets that decision.
7. Tokens, authentication headers, and response bodies must not be logged.
8. The review workspace sends explicit provider review commands. It shows success only after the provider accepts the command.
9. The left navigator groups changed files by path, supports folder collapse and case-insensitive path filtering, and keeps the original provider file index when a filtered result is selected. File-state Octicons use Primer semantic foreground tokens: success for additions, danger for deletions, attention for renames, and muted for edits, with separate light/dark values. Its GitHub-style filter menu lists file extensions with local counts, supports independent extension selection, an `Only manifest files` restriction, and a `Viewed files` visibility toggle. The `Files changed` toolbar has a GitHub sidebar toggle: hiding the tree also removes its divider and resize hit target so the diff fills the workspace; showing it restores the retained width. Crossing below Primer `$width-md` (768px)—matching GitHub's `Layout--flowRow-until-md` + `sidebarPosition-flowRow-none` `max-width: 767.98px` sidebar rule—auto-collapses the tree; crossing back above auto-expands it. The toolbar toggle always works at any width, so the tree can be reopened while still narrow. The application window minimum width is 800px, so normal desktop resizing does not reach this internal breakpoint; constrained-host and direct workspace tests still cover it. File-tree and diff rows are virtualized so resizing and scrolling instantiate only visible delegates. Its divider resizes live with the pointer, with a 220 px minimum, a 520 px absolute maximum, and a dynamic maximum of 45% of the review width. During native macOS live resize, the workspace keeps its last stable internal geometry and renders each visible non-hunk code row as one plain monospace text node; releasing the edge applies the final geometry once and restores token-colored syntax text.
9.1. PR Diff virtualization is owned by the replaceable `usher-virtual-list`
facade, not Material `ListView`. Stable-width display-column metrics produce
exact row extents. Ordinary scrolling updates a stable bounded overscan model;
direct-thumb dragging and release render identical wrapped content. The full
lazy line model remains the source for search, selection, and copy and is never

10. Filtering and file-to-file navigation are local model operations. They must not reload the diff or introduce an additional provider request.
10.1. Opening the commit selector lazily reuses the provider-neutral PR commit list. Saving `All commits` restores the original cached detail without a network request. Saving a contiguous range compares the commit before the selected start (or the PR base SHA) with the selected end through the provider repository compare endpoint. Changing ranges invalidates highlighted/source caches and stale range responses cannot replace a newer selection.
11. The normalized `viewed` field controls the local `Viewed files` filter. Provider adapters whose similarly named field has different semantics must normalize it to `false` instead of exposing that provider field as review progress.
12. Syntax highlighting is produced in Rust with `syntect` using the selected file path; Slint receives styled token models and never parses source languages. The Files changed code column supports GitHub-style drag selection (Unified and Split) without a separate selection mode: selection geometry uses the measured monospace cell advance and display columns (including tabs and wide glyphs), wrapped rows keep Slint auto-wrap (`TextInput.word-wrap`) and use its native UTF-8 selection geometry so continuation-line double-click paints the complete logical word, and line-number gutters plus `+`/`-` markers stay outside the selectable region. Wrapped Unified gutter glyphs use the same natural first-line font box as wrapped code; unwrapped rows retain the nominal 22px slot. Double-click expands to the same character-class run (alphanumeric/`_`, whitespace, or other punctuation), and triple-click selects the full code column line; the multi-click streak is owned by the review workspace so virtual-window projection cannot break the gesture. ⌘/Ctrl+F opens a compact editor-style find bar in the selected-file toolbar (GitHub's PR Files changed page has no first-party find chrome and relies on browser find-in-page; Usher mirrors the CodeMirror/GitHub file-editor find panel: query, `current/total` or `No results`, previous/next, and close). Matching is case-insensitive over copyable code columns only and uses `usher-search` for Unicode-safe non-overlapping occurrences. Enter/Shift+Enter navigate each occurrence in source order with wraparound, including multiple matches on one logical line. Viewport reveal follows Blink `CenterIfNeeded`: a fully visible active match does not scroll; a partially or fully hidden match is centered and clamped to content bounds. Wrapped code resolves the occurrence to its visual subline first, so multiple visible matches on one visual line change only highlight/counter. The PR adapter performs one command-time calculation and at most one viewport write; it has no Find positioning timer, viewport observer, recycled-row geometry report, or persistent reveal state. Width/height changes and scrolling never reposition the active match. Mounted overscan rows use bounded paint-only match models: the active match is Blink orange `#ff9632` and other matches are Blink yellow `#ffff00`; these models never read or write viewport state. Escape closes find before clearing a selection. Hunk headers (`@@ … @@`) and meta rows are never selectable and are omitted from ⌘/Ctrl+A ranges and clipboard text, matching GitHub. Cross-row pointer hit testing walks the projected model's actual per-row wrap heights and word-wrap boundaries, so dragging forward or backward into a wrapped endpoint can stop at an exact character instead of treating visual rows as logical diff rows. The diff Flickable must not arbitrate pointer drags: vertical code drags remain selection gestures, while wheel/touchpad and scrollbar scrolling stay enabled. Multi-line ranges copy newline-joined plain text through a silent clipboard write; ⌘/Ctrl+A selects the complete Unified diff or the active Split pane, and Escape clears the active range. Switching file, tab, diff view, or the line-model revision clears selection. Selection must preserve exact virtualization: no whole-file TextInput or duplicate token model may be created; only mounted overscan delegates own lightweight read-only TextInput instances for wrapped selection rendering.

13. Tabs expand to four-column stops before highlighting. Visible token and whitespace widths use the selected monospace face's measured advance. Display columns (including double-width CJK characters) remain the fallback while no measured line is available.
14. PR list, PR detail/diff, and repository-source requests are dispatched by the current project's persisted `repo_type`. The dispatcher also verifies that it matches `remote_repo`; no caller may silently fall back to another provider.

Conversation 时间线的 commit 标题/短 SHA，以及 Commits Tab 的 commit 标题/短 SHA，都作为应用内 commit detail 入口。点击后复用当前 PR 的 Files changed 页面，将 commit selector 原子地设为该 commit 的单项范围；如果 Commits 内容尚未加载，先在后台加载并按 SHA 定位，再应用范围。复制 SHA 操作保持独立，不得触发详情导航。Commits Tab 行背景在指针位于该行任意处（含标题、短 SHA、复制、相对时间、kebab）时保持淡底，因为子级 TouchArea 会抢走父级行 hover；标题下划线与短 SHA 高亮仍仅在指针落在对应控件上时出现，不得由行背景 hover 单独连带触发。标题 hover 时保持正常前景色，并按每一行换行后的实际字形使用文本原生下划线；不得变成强调蓝色，也不得用一个矩形横线贯穿整个标题块。短 SHA 默认是透明背景、无边框的纯文字；只有直接 hover 时才显示按文字宽度加内边距的 GitHub 风格圆角 control-hover 淡底（浅色 `#eaeef2` / 深色半透明，而不是与行底相同的 page `bg-muted`，以便在白底与行淡底上都可辨认），并在上方显示 `View commit details`。当 message 在标题之外还有 body 时，标题旁带边框的 muted kebab（展开时使用 Primer accent-muted 底色与强调色图标）仅内联展开/收起 body，不进入详情。展开互不排斥：展开一条不会收起其他已展开条目。只有标题（和短 SHA）打开详情——行背景与 kebab 不是导航目标。展开态遵循 GitHub 顺序：首行标题/kebab/SHA，其下为按换行高度贴合的 message body，再下为带头像的作者行（`{author} committed {relative}`），两者之间保留紧凑呼吸间距，且 body 不得与作者行重叠。Commits Tab 标题超出列宽时换行显示，不得用省略号截断；作者/时间行与行高随换行增高。相对时间与作者行同高、同用继承的应用字体，并与 `committed` 保持基线对齐。Message 展开按钮必须跟随换行标题最后一个字形后的精确光标位置。收起时 SHA 与复制操作在完整“标题 + 作者”摘要区内垂直居中；展开时则在整个展开行内垂直居中。
36. 展开或收起 commit message 时必须保持当前 ListView viewport 与被点击控件的屏幕位置；实现应原位更新现有 model 行，不能替换整个 model。当前行以上内容保持不动，只允许后续行下移或上移。

    使用 readiness 控制操作可用性，但不得再绘制重复的 readiness/state 徽标。

    在 Tab 需要 overflow 前隐藏。

## Rewrite checklist / 重写清单

- Keep repository configuration (`provider type`, `provider project id`, `remote URL`) persistent and project-scoped; keep the list/review cache session-scoped and disposable.
- Split the implementation into UI, workflow/controller, provider adapters, HTTP/auth, and persistence layers. Only adapters know provider response shapes.
- Preserve the normalized records and error/loading states above as the cross-layer API. A web, mobile, or native UI can replace Slint without changing provider adapters.
- Treat remote reads as cancellable or sequence-guarded. Prefer cancellation where the target runtime supports it, but preserve the “latest request wins” rule either way.
- Use immutable base/head references for expanded source. Do not expand context from a mutable branch tip.
- Keep per-file highlighting and source contents cached only for the active review; invalidate on project switch, PR switch, close, or whitespace-mode change as appropriate.
- Model remote review, merge, and revert as explicit commands with their own capabilities, confirmation, stale-response protection, and error behavior.

- 将仓库配置（`provider type`、`provider project id`、`remote URL`）持久化并按项目隔离；将列表/审核缓存视为可丢弃的会话状态。
- 将实现拆分为 UI、workflow/controller、Provider adapters、HTTP/auth 与持久化层；只有 adapter 知道 Provider 响应结构。
- 将上述归一化记录和 loading/error 状态作为跨层 API。Web、移动端或原生 UI 可替换 Slint，而无需改动 Provider adapter。
- 远端读取必须支持取消或请求序列防护。目标运行时若支持则优先取消，但无论如何都要保留“最新请求优先”的规则。
- 展开源码必须使用固定的 base/head 引用，不能从可变的分支 tip 展开上下文。
- 每文件的高亮和源码内容只缓存于当前审核；在项目、PR、关闭或空白模式切换时按需失效。
- 远端 review、merge 和 revert 必须建模为显式命令，拥有独立的能力、确认、旧响应防护和错误行为。
